# Living World Engine

SillyTavern 的角色生活与世界状态扩展。编导根据世界事实与玩家行动写出剧情。正文显示后，记录员提取正文变化，也可以按本楼经过的故事时间推演离场核心角色的生活。世界引擎校验后保存两类变化。

## 开始游玩

1. 打开酒馆的扩展菜单，展开 **Living World Engine · 世界引擎**。
2. 选择一个聊天，打开「设置世界起点」。可以填写自己的场景，或点「填入旅店示例」试用。
3. 检查故事时间、地点、角色位置和已有记忆，点击「建立世界起点」。已有对话视为起点前的历史。「设置核心角色」可以从起点角色中登记最多八位，已有存档可以直接设置。旅店示例预设了阿青和阿岚两位核心角色。
4. 照常发消息、重答和切换候选。正文正常显示后，面板会更新世界记录。一次记录调用尚在进行时，下一轮会先等该调用结束，再读取状态。

记录员默认使用当前酒馆连接。也可以在「状态记录员的连接」中选择已保存的酒馆连接，或选择「自定义接口」，直接填写 OpenAI 兼容 API 地址、密钥和模型 ID，再点「保存记录员接口」。地址可以填 API 基础地址（例如 https://api.example.com/v1），也可以填完整的聊天补全地址。自定义密钥保存在当前酒馆账号的世界引擎数据目录中。同一地址留空会保留旧密钥，更换地址时可以填写新密钥。

每轮正文生成后多一次记录请求，发送最后确认的世界状态、核心角色资料和待记录的正文。故事时间有推进时，这次请求也让记录员概括离场核心角色的生活进展。后台变化经过时段和一致性检查后，随当前回复一起保存。

「测试连接」会用已保存的接口发送一条简短测试请求，面板显示最近一次结果。修改地址、模型或密钥后，测试结果会随新配置重新记录。

## 与酒馆上下文的关系

前端使用酒馆的生成拦截器及扩展提示词入口，把相关世界事实、必要约束和带归属的角色记忆放入本轮提示。酒馆按原流程组织角色卡、预设、世界书、聊天历史和模型连接。「本轮发给编导的世界资料」显示从实际生成请求中截取的引擎片段。随新回复保存后，刷新或切换候选可以查看对应记录。

后端插件按酒馆账号、角色或群组标识和聊天隔离存档。记录包含原文依据。账目、库存、路线耗时、时序与记录来源经过一致性检查。每个候选的变化只应用到它所对应的聊天历史，刷新后可从存档还原。

## 状态和冲突

- 时钟以故事中的日、小时、分钟表示。普通对话的耗时可由记录员估计。路线按方向和移动方式记录分钟数，已动身和已抵达分别记录。
- 每条记忆记录所属角色、内容、获知途径、故事时间和原文依据。亲历、听闻与推测各自保留来源。
- 正文由酒馆直接显示。若记录与事实冲突，面板显示有问题的变化与对应原文，存档保留最后一次确认的状态。编导可以在下一段补足因果，记录员据补写重新提取，或者由玩家使用酒馆的重答功能。
- 切换已有候选会恢复相应状态。从某楼截断后文会回到最后保留楼的状态。中间删楼或改动后仍有后文时，面板提示重新建立起点。重建会保留此前存档的备份。
- 「当前世界记录」区分正文和幕后事件，可展开查看当前状态 JSON。幕后提案未通过时，面板显示原因，已确认的前台事实仍会保存。记录请求失败时，可使用「补记当前回复」。

当前版本针对酒馆单聊中的多角色叙事。记录员的提取质量和出场判断取决于所用模型。硬设定以文字约束提供给编导，完整理解自然语言规则仍依赖模型。长线策划和长期记忆压缩属于后续阶段。重命名或复制聊天需要为新聊天建立起点。

## 手机酒馆安装

需要 SillyTavern 1.19.0 或更新版本。手机独立运行酒馆时，在 Termux 安装服务端插件；如果手机浏览器访问的是电脑或云端的酒馆，则在运行酒馆的那台机器上安装。界面扩展在手机浏览器里用酒馆的安装按钮添加。

1. 在酒馆目录安装服务端插件。仓库可直接克隆，无需登录 GitHub。下方路径以 Termux 的常见安装位置为例。

   ```sh
   cd ~/SillyTavern
   node plugins.js install https://github.com/MYming-yue/living-world-engine.git
   ```

2. 在酒馆的 `config.yaml` 中设为 `enableServerPlugins: true`，然后重启酒馆。用浏览器访问当前酒馆地址下的 `/api/plugins/living-world-engine/health`，看到 `"ok": true` 即可继续。
3. 在手机酒馆的「扩展程序 → 安装扩展程序」粘贴同一个仓库地址。安装后刷新页面，打开「Living World Engine · 世界引擎」。
4. 填好手机酒馆的主连接，在世界引擎面板配置记录员，点「测试连接」，然后在测试聊天中建立世界起点。手机独立实例有自己的存档和连接配置。若 Gemini 反代运行在电脑上，主连接继续使用手机原来可以访问的反代地址。

仓库根目录的 `manifest.json` 供酒馆安装界面扩展，`package.json` 的 `main` 供酒馆加载服务端插件。两步都从同一个仓库的默认分支安装。

已安装的手机实例可以在酒馆的「管理扩展程序」更新界面扩展。在酒馆目录执行 `git -C plugins/living-world-engine pull --ff-only` 更新服务端插件，重启酒馆后刷新浏览器。

## 电脑本机安装与更新

适用 SillyTavern 1.19.0 和 Node.js 22 以上。酒馆加载 `server/` 中的服务端插件，浏览器加载 `extension/` 中的界面扩展。

在此项目目录运行：

```powershell
pwsh -File ./scripts/install.ps1 -EnableServerPlugin
```

脚本将插件复制到同级 `sillytavern` 安装的插件目录，将界面扩展装入默认账号，并启用酒馆的服务端插件加载。其他安装路径使用 `-SillyTavernPath`，不同数据目录或账号使用 `-DataRoot`、`-UserHandle`。安装后重启酒馆。存档放在每个酒馆账号的数据目录下的 `living-world-engine/`。

接口依据为 [酒馆 UI 扩展文档](https://docs.sillytavern.app/for-contributors/writing-extensions/)和[服务端插件文档](https://docs.sillytavern.app/for-contributors/server-plugins/)。

## 验证

`npm test` 检查候选隔离、幂等结算、时空、知情边界、冲突与回退。测试无需项目依赖。

`scripts/verify-sillytavern.mjs` 用实际酒馆页面和服务端检验接线，模型响应使用固定样例。把扩展安装到独立测试数据目录，运行监听 8019 的酒馆，设置 `LWE_PLAYWRIGHT_MODULE` 指向本机 Playwright Core 的 `index.mjs`，再运行 `node scripts/verify-sillytavern.mjs`。测试会创建一个专用聊天。Chrome 使用无头模式运行。
